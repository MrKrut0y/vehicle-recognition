# Рабочий отчёт по курсовой

Тема: «Автоматизация заполнения базы данных объектов распознавания средствами компьютерного зрения». Объект исследования — транспорт на видеозаписи одной камеры в городе Глазове. Этот файл фиксирует найденные сведения, принятые предварительные решения и нерешённые вопросы. Он не заменяет текст курсовой работы.

## 30.10.2026 — источники видео и модели распознавания

### Что удалось найти

- «Гарант Глазов» публикует список городских камер с адресами и направлением обзора. В частности, камера по адресу К. Маркса, 8 обозначена как наблюдающая за перекрёстком улиц Толстого и К. Маркса. Оператор сообщает, что городские камеры можно бесплатно смотреть в мобильном приложении.
- «Глазов.NET» предлагает карту онлайн-камер и запрос архивной видеозаписи. Веб-кабинеты камер обоих операторов открывают страницу входа платформы «Форпост».
- Платформа «Форпост» технически поддерживает RTSP-доступ с проверкой логина, пароля и прав пользователя. Это возможность платформы, а не подтверждение доступа к конкретной камере «Гарант Глазов».
- Для обнаружения транспорта подходит готовая модель YOLOv8s (`yolov8s.pt`): её классы включают легковой автомобиль, мотоцикл, автобус и грузовик. Для номера и цвета нужны дополнительные модели.
- Найден проект ANPR-System с готовыми моделями YOLOv8 для поиска российских номеров и CRNN для чтения символов. Его готовая программа использует OpenCV для коррекции перспективы, поэтому при требовании не использовать OpenCV потребуется отдельно решить эту часть обработки. Заявленная автором точность не проверена на видео из Глазова.
- Найдена готовая модель EfficientNet-B4 для определения цвета автомобиля по его изображению. Она различает 14 цветов; качество на выбранной камере пока неизвестно.

### Предварительное решение

Основной кандидат на источник видео — «Гарант Глазов», одна камера на перекрёстке Толстого и К. Маркса (К. Маркса, 8). Причина выбора: оператор называет адрес и объект наблюдения, а перекрёсток подходит для регистрации проезжающего транспорта. Окончательный выбор зависит от проверки ракурса, разрешения и доступности видеопотока.

План обработки: получение разрешённого видеопотока; обнаружение транспорта YOLOv8; отслеживание одного транспортного средства на последовательных кадрах; отдельное распознавание номера и цвета; запись одного события в MySQL на транспортное средство. Нечитаемый номер или сомнительный цвет следует оставлять пустыми и помечать для проверки. Первоначальную структуру БД позднее понадобится уточнить для хранения отдельных оценок достоверности признаков.

### Трудности и вопросы

- Не найдено публичного подтверждения, что «Гарант Глазов» или «Глазов.NET» выдают стороннему приложению RTSP/HLS-поток либо API-доступ к городским камерам.
- Просмотр в приложении и возможность запросить архивную запись сами по себе не дают оснований использовать поток для автоматической обработки.
- Читаемость номеров нельзя оценить без реальных кадров: она зависит от расстояния, ракурса, освещения, движения и разрешения.
- Готовая модель цвета заявлена для вырезанного изображения автомобиля; работа с мотоциклами, автобусами и грузовиками требует проверки.

## 01.11.2026 — работа до получения доступа к городской камере

Пока нет потока из Глазова, можно подготовить и испытать основную часть системы на заранее записанном видео. Организаторы AI City Challenge открыли для скачивания набор видеозаписей дорожных камер 2021 года для задачи подсчёта транспорта; записи подходят для проверки обнаружения, отслеживания и исключения повторных записей одного автомобиля. В этом наборе номера скрыты, поэтому проверять на нём чтение госномеров нельзя.

Порядок дальнейшей работы:

1. Выбрать один короткий разрешённый видеоролик с неподвижной дорожной камеры и зафиксировать его источник и условия использования.
2. Подготовить обработку видео YOLOv8: тип транспорта, сопровождение объекта, одно событие на одно транспортное средство.
3. Проверить запись события в черновую MySQL-базу и уточнить поля для отдельных результатов распознавания типа, номера и цвета.
4. Отдельно проверить готовую модель чтения российских номеров на изображениях с видимыми номерами и модель определения цвета на изображениях автомобилей. Не переносить эти результаты автоматически на городскую камеру.
5. Составить ручную контрольную выборку и измерить пропуски, ложные обнаружения, дубли записей, правильность номера и цвета.
6. Подготовить для курсовой разделы выбора источника видео, архитектуры системы, критериев оценки и ограничений. После получения реального потока заменить тестовый источник, проверить ракурс, день/ночь и повторить измерения.

Источник тестовых дорожных видео: https://www.aicitychallenge.org/ai-city-challenge-dataset-access/ ; описание набора 2021 года: https://www.aicitychallenge.org/2021-data-and-evaluation/

## 01.11.2026 — как проверять отслеживание транспорта

Для первого опыта взять короткий ролик одной неподвижной дорожной камеры. Задать на изображении контрольную линию, которую пересекают проезжающие транспортные средства. Вручную составить контрольный список пересечений: порядковый номер машины, примерное время, тип, приметы (например, цвет). Неподвижные и не пересёкшие линию машины в этот список не включать.

Система должна показывать рамку объекта и временный идентификатор отслеживания на каждом обработанном кадре. Для каждой машины, пересёкшей контрольную линию, в БД должно появляться одно событие. Сравнить события с ручным списком и отдельно подсчитать: пропущенные машины, лишние события, дубли одной машины и смены идентификатора во время её движения. Проверить случаи сближения машин, частичного перекрытия, поворота и кратковременного выхода из видимой области.

Идентификатор отслеживания действует только в пределах обработки конкретного видеопотока/сеанса: его нельзя считать государственным номером или постоянным идентификатором автомобиля. После проверки на учебном ролике те же измерения повторить на разрешённой записи камеры из Глазова.

## 01.11.2026 — подготовка первого запуска YOLOv8

- На рабочем компьютере обнаружены Python 3.14.5 и FFmpeg 8.1.1. Команда YOLO пока не установлена; видеофайла в папке курсовой нет. Наличие подходящего графического ускорителя не установлено, поэтому первый опыт можно планировать на процессоре.
- По официальной документации Ultralytics готовая модель `yolov8s.pt` загружается автоматически при первом запуске. Её не нужно обучать заново, чтобы получить первые рамки вокруг стандартных классов транспорта.
- Минимальная последовательность для первого опыта: создать отдельную среду Python в папке проекта; установить пакет Ultralytics; проверить распознавание на одном изображении; затем запустить режим отслеживания на коротком видео; посмотреть сохранённый ролик и сравнить временные идентификаторы объектов с ручной проверкой. Запись в MySQL, распознавание номеров и цвета подключать после успешной проверки базового прохода видео.
- Уточнение: YOLO — обученная нейросетевая модель для обнаружения объектов, а OpenCV — библиотека обработки изображений. Они не являются взаимозаменяемыми средствами. Требование пользователя однозначно закрепляет YOLO как основу распознавания; допустимость OpenCV как вспомогательной зависимости пока не уточнена.

Источники: https://docs.ultralytics.com/quickstart/ ; https://docs.ultralytics.com/models/yolov8/ ; https://docs.ultralytics.com/modes/track/ ; https://pytorch.org/get-started/locally/
